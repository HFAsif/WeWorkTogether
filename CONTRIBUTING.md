# Contributing to WeWorkTogether

Thank you for helping improve this collaboration starter. Contributions should be useful, traceable, and small enough to review.

## Before you start

1. Read the README and search existing issues and pull requests to avoid duplicate work.
2. For an improvement, open an issue explaining **why it matters** and what a successful result looks like.
3. For a security-sensitive report, do not disclose credentials or exploit details in a public issue.

## Make a focused change

1. Branch from the current default branch.
2. Prefer one concern per branch and pull request.
3. Keep documentation accurate and examples runnable where relevant.
4. Do not commit generated binaries, machine-specific paths, or secrets.
5. Summarize what changed and preserve any uncertainty.

## Verify it

Before opening a pull request:

- Read the rendered Markdown for formatting, working relative links, and spelling.
- Confirm any code examples work in their stated environment.
- Check that the diff contains only intentional changes.
- Describe testing honestly: **not run** is better than inventing a test result.

## Submit and merge

Use the pull-request template. Explain the problem, approach, validation, and any remaining risk. Review expectations depend on the project's impact: a minor documentation change may be safe to self-merge, but security-sensitive or production changes should receive appropriate review.

After merging, close any issue actually resolved and link the merged pull request. Do not close unrelated issues to inflate activity.

## Collaboration etiquette

Be respectful, give actionable feedback, and credit actual collaborators for substantive contributions. Do not fabricate co-authors, stars, accepted answers, or test results for GitHub achievements.
